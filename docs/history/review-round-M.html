二、已实施修复详解

N1 · YAML 注入（高危）→ server/src/engine.rs

原代码把节点名直接写进 proxies: ["{p.name}"]。节点名来自订阅/用户，若含 :、#、" 或前导特殊字符，会破坏 YAML 结构，甚至注入额外代理组/规则。

修复：新增 escape_yaml_scalar()，对需要引号的标量加双引号并转义内部 "；仅在含特殊字符时才加引号（保持普通名可读）。

fn escape_yaml_scalar(s: &str) -> String {
    let needs_quote = s.is_empty()
        || s.starts_with(['!','&','*','%','@','`','"','\'','#','|','>','?'])
        || s.contains([':', '#', '\'', '"', '\n', '\t'])
        || matches!(s.parse::<f64>(), Ok(_));
    if needs_quote {
        format!("\"{}\"", s.replace('\\', "\\\\").replace('"', "\\\""))
    } else {
        s.to_string()
    }
}
// 调用处：
let _ = writeln!(cfg, "    proxies: [\"{}\"]", escape_yaml_scalar(&p.name));

单测覆盖：: / # / 引号 / 纯数字 等用例 → pass。

N2 · 测速指标错位（高危）→ server/src/lib.rs

tcp_ping_all 通过 channel 按"完成顺序"回传结果，而 engine_http_latency / bandwidth 按"输入顺序"回传。原 for (r,h) in results.iter_mut().zip(http) 把错位指标对齐，导致 A 节点的延迟/带宽被写到 B 节点——直接污染评分与排序。

修复：HTTP 与带宽结果改为 HashMap<fingerprint, value>，按 fingerprint 对齐回填：

let http_map: HashMap<&String, f64> = http.into_iter()
    .enumerate().map(|(i,&fp)| (fp, lat)).collect(); // 以 (fp, lat) 元组收集
for r in results.iter_mut() {
    if let Some(l) = http_map.get(&r.fingerprint) { r.http_latency_ms = *l; }
    if let Some(b) = bw_map.get(&r.fingerprint) { if let Some(b)=*b { r.download_speed_bps=Some(b);} }
}

N3 · DB 写串行化（中）→ server/src/lib.rs

新增 persist_lock: Arc<Mutex<()>> 字段，persist_all 在 db.save_all(&subs) 前后加锁，避免并发请求同时触发全量写造成 SQLite 锁竞争（store 原地 mutate 本已缓解更新丢失，此锁为防御层）。

let _guard = state.persist_lock.lock().unwrap();
db.save_all(&subs);

N5 · Tauri 端口与就绪（中）→ app/src/main.rs + tauri.conf.json

旧：tauri.conf.json 静态窗口硬编码 http://127.0.0.1:3005，且先于 server 启动完成开窗 → 白屏；与 server 实际 SUBHUB_PORT 脱节。

新：main.rs 读取 SUBHUB_PORT（默认 3005），在 setup 中轮询 /api/health 直到就绪，再以 WebWindowBuilder 动态开窗；tauri.conf.json 删除静态 windows。

static ENGINE_DIR_SEQ: AtomicUsize = AtomicUsize::new(0);

三、主动跳过的项（建议单独立项）

N6 · CORS 全开 *

当前 webui 同源部署 / Tauri 本地打包，无跨域需求；盲目加白名单反而增加维护成本。仅在确实要跨域访问时才收口。

N8 · 流式/超时上限

请求量小，全局超时层收益低。可后续在 tower_http::timeout 加一道上限。

M1 · 单引擎批处理

当前每节点一个进程（已限并发 4 + CREATE_NO_WINDOW）。改为单引擎多节点批测需重写 config/拉取逻辑，风险高，单列。

M8/M9 · 增量 upsert / 分页下推

save_all 全量重写在订阅规模大时偏重；改为增量 + 列表分页可提升性能，但涉及存储模型改动。

M11 · 本地订阅幂等

重复导入同一本地订阅的合并策略需明确语义，单列评估。

L 系列 · 低危打磨

日志结构化、配置校验友好化、错误文案统一等，纯打磨项，可后续批量处理。
