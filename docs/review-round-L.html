一、已实施改进（T68–T73）

T68 · 解析正确性 已实施

位置问题修复
parse.rs clash / sing-box 端口端口 70000 经 as u16 静默截断为 4464，产生连不上的幽灵节点改用 (1..=65535).contains(&p) 校验，越界则丢节点
parse.rs split_authority端口 ==0 会被接受端口 0 直接返回 None
parse.rs parse_ssrSSR 端口可能为 0 / 越界加 (1..=65535).contains 范围过滤
parse.rs sing-box tls H2原 is_some() 把 tls:false 也强制为 true，明文节点被误加成 TLS区分 Bool(b)→b / 对象→true / 缺省→false
parse.rs vmess tls M5仅识别字符串 "tls"，布尔 true 被判 false同时接受 "tls"|"true" 与 JSON 布尔
parse.rs URI 行 M10update-url: / https://rules… 被当 Http 节点仅解析已知 scheme（is_known_scheme）

T69 · 评分与可用性污染 已实施

位置问题修复
model.rs无法区分「真实引擎测得的带宽」与「无引擎时的 TCP 估算」新增 bandwidth_measured: bool（#[serde(default)]，默认 false）
lib.rs persist_results无引擎时仍把 TCP 估算计入 0.40 带宽权重，污染评分仅当 bandwidth_measured 为真才计入带宽分；引擎 HTTP 可达即判 available

T70 · 资源泄漏与静默失败 已实施

位置问题修复
engine.rs H1引擎进程在 ? 提前返回路径上泄漏（进程 + temp 目录）新增 EngineGuard{child,dir} + Drop（kill + 删目录），所有出口自动清理
db.rs H3save_all 的 let _ = 把持久化失败吞掉改为 eprintln! 打印失败原因与订阅 id

T71 · 正则静默清空 已实施

位置问题修复
ops.rs H4导出过滤器正则写错时，导出被静默清空（include 模式）或全量导出（exclude 模式）apply() 返回 Result<Vec<Proxy>, String>；正则编译失败即时返回可读错误

T73 · 服务错误体 + 前端错误展示 已实施

位置问题修复
lib.rs /api/export & /sub正则/转换错误被 ? 静默改用 map_err(|e| (StatusCode::BAD_REQUEST, e)) 返回 400 + 错误文本；/sub?top_n=N Top-N 已支持
webui/app.js导出失败无任何提示api() 把后端错误响应体带入 throw；btn-export 加 try/catch 在 #export-info 显示「导出失败: …」
