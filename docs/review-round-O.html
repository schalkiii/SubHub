1. 本轮发现与处理

ID严重度问题处理
Q1 高 client_with_proxy 未设重定向策略（默认跟随 10 跳，存在重定向炸弹/SSRF 风险）；且远端订阅响应体无上限，resp.text() 整段缓冲 → 内存耗尽 DoS（DefaultBodyLimit 只限请求体，不限响应体）。 新增 redirect::Policy::limited(5) 限制重定向链；新增 fetch_subscription_text() 助手，按 Content-Length 预检 + 读取后长度守卫，超过 16 MiB 直接拒绝。替换 add_subscriptions 与 do_refresh_one 两处原始 fetch。
Q2 中 incremental_update 在 refresh 时只保留 latency/available/download 等字段，漏掉 bandwidth_measured → 已测节点的真实带宽信号被 score_proxy 忽略，Top-N 排名每次刷新后静默变化。 补 merged_p.bandwidth_measured = o.bandwidth_measured;。新增单测。
Q3 中 fingerprint() 对 Trojan/Hysteria2/Socks5/Http 仅用 password，SNI/Host/Path 不同的真实节点被误判为重复并静默丢弃；Wireguard/Other 凭证为空，同地址两节点也会碰撞。 凭证串扩展为 password|sni|host|network|path；Wireguard/Other 分支也纳入 sni/host/network/path。新增单测（不同 SNI 的 Trojan 必须不同 fp）。
Q4 中 订阅 URL 常带鉴权 token（https://user:pass@host/sub?token=），add_subscriptions 的 eprintln!("fetched {url}: …") 把完整 URL（含密码）写进进程日志。 新增 redact_url() 剥掉 userinfo 与 query string，日志改为 redact_url(url)。
Q5 低 webui loadDashboard() 的 api("/api/dashboard") 未包裹 try/catch，一旦报错整个函数中断，连带着 loadSubs / loadTrends 都不执行 → 仪表盘标签页静默白屏。 包裹 try/catch：失败时显示错误卡片并仍加载订阅列表与趋势，标签保持可用；并对 by_type/total 做空值兜底。
Q6 低 ① proxy_test 超时提示写「(5s)」但实际超时是 Duration::from_secs(15)，误导用户；② add_subscriptions 仅在代理 URL 语法合法即记住为默认抓取代理，连不通也会被记住。 ① 提示改为「(15s)」；② 默认代理改为「仅当本次批量中至少一个订阅实际抓取成功」后才持久化。

3. 主动跳过 / 待立项项

本轮未修改（收益低于风险/工作量，或非当前崩溃/数据错误根因）：

  • 重定向 SSRF 到内网：本工具为绑定 127.0.0.1 的单机本地程序，响应体仅被解析为节点、从不回传，实际泄露面极小；已用 limited(5) 兜底重定向炸弹。如需更强隔离可改 Policy::none()（会破坏合法 301/短链）。
  • M1 单引擎批量 / M8-M9 增量 upsert 与分页 / M11 幂等导入 / L 系列打磨：需较大重构，建议单独立项。
  • Wireguard 私有密钥建模：Proxy 当前未建模 wireguard key，故两个 wireguard 节点仅靠 type|server|port|name 区分；属数据模型扩展，非本轮范围。
